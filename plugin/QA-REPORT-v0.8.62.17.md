# QA-REPORT — v0.8.62.17

**تاریخ:** 2026-09-27
**موضوع:** خروجی اکسل کامل گزارش Workflow — رویدادها + ریز وضعیت هر مرحله + داده‌های هر مرحله + pivot خلاصه

## درخواست کاربر
در بخش Workflow رفع ناقصی → گزارش‌گیری‌ها: هر پرونده مراحل اقدام دارد (ثبت تماس، ثبت نتیجه بررسی،
ارسال به تأیید مالی، اصلاح مبلغ اعلامی و تکمیل، تکمیل پروفایل و بارگذاری) و هر مرحله زیر وضعیت و
داده‌های خودش را دارد. این وضعیت‌ها و ریز وضعیت‌ها باید در گزارش اکسل بیایند.

## پیاده‌سازی

### 1) دکمه خروجی اکسل (گزارش‌های رفع ناقصی و مالی)
- `render_reports()`: دکمه «خروجی اکسل کامل (پرونده‌ها + اقدام‌ها و ریز وضعیت‌ها + خلاصه)» کنار
  Export CSV — `admin-post.php?action=bcrm_deficiency_export_excel` با همان nonce `bcrm_deficiency_export`.

### 2) `Biawin_CRM_Deficiency_Workflow::export_excel()` — XLSX سه‌شیتی
- **شیت «پرونده‌ها»:** همان ستون‌های CSV + کارشناس رفع ناقصی/مالی + وضعیت عودت.
- **شیت «اقدام‌ها»:** تک‌تک رکوردهای `case_actions` (سقف 20,000، ترتیب زمانی صعودی) با ستون‌های:
  Case / CustomerID / مشتری / رویداد (برچسب فارسی از `event_label()`) / از وضعیت / به وضعیت /
  کاربر / زمان / **زیر وضعیت / نتیجه** / مبلغ ادعایی مشتری / اختلاف تاییدشده / مبلغ اعلامی
  اصلاح‌شده / مبلغ تایید نهایی / مبلغ فاکتور برگشتی / شماره فاکتور برگشتی / شماره تماس ثبت‌شده /
  وضعیت عودت / تعداد فیش / جمع مبلغ فیش‌ها / تاریخ پیگیری / توضیحات.
  - زیر وضعیت از `metadata_json` هر رویداد: `contact_outcome` (پاسخ داد، پاسخ نداد، خاموش،
    در دسترس نیست، شماره اشتباه، پیگیری مجدد) → `deficiency_result` (۸ نتیجه بررسی) →
    `finance_result` (با/بدون فاکتور، عدم تأیید) → `document_type` → `refund_status`.
- **شیت «خلاصه»:** pivot شمارش هر (رویداد × زیر وضعیت)، مرتب نزولی.

### 3) `xlsx_write_multi()` — مولّد XLSX چندشیتی بدون وابستگی
- inline strings + ZipArchive؛ flush کامل بافر خروجی (`ob_end_clean`) مثل اصلاح Elementor v0.8.62.14؛
- نام شیت‌ها از کلیدهای آرایه، sanitize تا سقف ۳۱ کاراکتر اکسل؛ روابط workbook برای همه شیت‌ها.

### 4) هندلر ادمین
- `admin_post_bcrm_deficiency_export_excel` → `handle_deficiency_export_excel()`:
  گیت همان گزارش‌ها (`view_deficiency_reports` / `view_finance_reports` / `bcrm_reports`) +
  `check_admin_referer('bcrm_deficiency_export')`.

## تأیید عملی (beyond static)
- رانر یک‌بارمصرف با ۱۰ رویداد واقعی (تماس → نتیجه → آپلود مدرک → ارسال به مالی با عودت → تأیید
  مالی → تکمیل) اجرا شد؛ فایل XLSX خروجی با ZipArchive باز و اعتبارسنجی شد:
  ۳ شیت با نام فارسی «پرونده‌ها | اقدام‌ها | خلاصه»، pivot درست (مثلاً «پرونده به مالی ارسال شد |
  عودت شده»، «نتیجه رفع ناقصی ثبت شد | ادعای واریز اضافه»)، ستون‌های مرحله‌ای (مبلغ ادعایی،
  تاریخ پیگیری، شماره تماس، وضعیت عودت) همگی موجود. رانر و فایل‌های موقت حذف شدند.
