# QA Report — v0.8.62.23

**تاریخ:** 2026-09-28
**موضوع:** پنل تایید مالی به سبک پلاگین فروش‌نت (کارت فیش‌ها + جمع مبالغ + پیش‌پرکردن باقیمانده) — با استایل خود CRM

## شرح تغییر

الگو از پلاگین دسکتاپ sales-network (صفحه «پیش‌فاکتورها و فاکتورها» و دکمه «✅ تایید مالی») برداشته شد، ولی **هیچ استایل/کلاس خارجی وارد نشد** — همه چیز با کلاس‌های خود CRM (`bcrm-card`، `bcrm-grid`، `button` وردپرس) و CSS جدید در `portal-fixes.css` (روشن + تیره) پیاده شد.

### صفحه پرونده (هر دو واحد رفع ناقصی/مالی)
- بخش **«فیش‌های این پرونده»**: برای هر فیش یک کارت شامل نام فایل، نوع (فیش بانکی)، زمان ثبت، توضیح (بدون پسوند «مبلغ فیش: …»)، **مبلغ همان فیش** و دکمه «مشاهده فیش».
- سه کارت جمع بالای پنل: **مبلغ اعلامی مشتری** / **جمع فیش‌ها (تعداد)** / **باقیمانده تا مبلغ اعلامی** (کارت باقیمانده در صورت صفر نبودن، قرمز `is-danger`).

### منبع مبلغ هر فیش
مبلغ از الگوی `مبلغ فیش: …` در ستون `note` ردیف‌های `attachments` خوانده می‌شود — همان چیزی که آپلود مرحله‌ای از v0.8.61 برای هر ردیف ذخیره می‌کند. پارسر ارقام فارسی و جداکننده‌های `,` و `،` را می‌فهمد (`Biawin_CRM_Normalizer::money`). ردیف بدون مبلغ → «نامشخص» و خارج از جمع.

### فرم ثبت نهایی تایید مالی (واحد مالی)
- خلاصه سه‌عددی (جمع فیش‌ها / مبلغ اعلامی / باقیمانده) بالای فرم.
- فیلد «مبلغ تاییدشده بدون فاکتور» placeholder آن = باقیمانده واقعی؛ JS (`data-bcrm-prefill`) هنگام نمایش سکشن، اگر فیلد خالی باشد آن را پر می‌کند — تایپ کاربر هرگز بازنویسی نمی‌شود.
- بقیه فرم (فیش مرتبط، تایید با فاکتور، عدم تایید) بدون تغییر منطقی.

## رفتارهای مرزی
- پرونده بدون فیش: پنل فیش‌ها رندر نمی‌شود؛ خلاصه فرم با صفرها نمایش داده می‌شود.
- سرریز (جمع فیش‌ها > مبلغ اعلامی): باقیمانده روی ۰ فِلور می‌شود (بدون عدد منفی).
- فیش‌های ردیف‌های قدیمی که مبلغشان داخل note بود ولی فرمتشان متفاوت است: «نامشخص» — هیچ عدد جعلی‌ای ساخته نمی‌شود.
