# PHASE 2 — Core Customer Journey Alignment (0.8.66.0)

**CRM رضایت‌سازی** · Baseline 0.8.65.0 · بدون تغییر schema، بدون Migration · Phase 3 شروع نشده است.

## ۱. قواعد پیاده‌شده

| قاعده | پیاده‌سازی |
|---|---|
| ناقص مسیر ندارد | `journey_gate()` حالت `incomplete`. همهٔ ورودی‌های انتخاب مسیر رد می‌شوند: فرم، AJAX، REST، ثبت خدمات و ثبت نارضایتی. پنل‌ها قفل‌اند. |
| کامل مسیر دارد | حالت `open`. فقط سه مسیر: ناراضی · بدون خدمات · خدمات مازاد. کلیدهای DB بدون تغییرند: `complaint` · `no_request` · `service_request`. |
| رفع ناقصی موجود؛ مالی اختیاری | گردش‌کار `deficiency_cases` دست نخورده است. هر ۴ مسیر تکمیل (تلرانس خودکار، اصلاح مبلغ، تکمیل خودکار پس از مالی، تصمیم نهایی) یک hand-off مشترک دارند: `after_completion()` → `on_deficiency_completed()`. |
| پس از تکمیل رفع ناقصی | همان `customer_id`، فاکتورها و پروفایل حفظ می‌شود. سپس: تگ موجود `COMPLETED_AFTER_DEFICIENCY` → پایان تخصیص تماس قبلی با وضعیت موجود `returned` (+`completed_at`، مشتری `status=new`، همان activity و audit «برگشت تخصیص») → نشانگر `deficiency_reallocation_required` → صف سرپرست. هیچ مسیری خودکار انتخاب نمی‌شود. |
| تماس جدید | حالت `awaiting_reallocation`، سپس `new_contact_required`، سپس `open`. مسیر فقط برای کارشناس تخصیص‌یافته‌ای باز می‌شود که پس از تخصیص تماس ثبت کرده باشد. ویرایش تماس قدیمی به ردیف جدید تبدیل می‌شود. سرپرست، کارشناس رفع ناقصی، مالی و هیچ فرایند خودکاری مسیر را انتخاب نمی‌کند. |
| ناراضی | انتخاب این مسیر = ثبت فرم نارضایتی (`create_complaint` موجود) → خدمات پس از فروش. کلیک بدون فرم چیزی ثبت نمی‌کند. معنای Outcomeها تغییر نکرده است. |
| بدون خدمات | `journey_state=no_request` + activity `no_service_archived`. فهرست «بایگانی بدون خدمات» قابل جست‌وجوست. بدون پرونده نارضایتی، بدون بیاوین، بدون گردش‌کار بعدی، و هیچ داده‌ای حذف نمی‌شود. |
| خدمات مازاد | `select_services()` گیت دارد. مسیر و پرونده‌های خدمت در یک تراکنش ثبت می‌شوند (R-07 رفع شد). مرز یکپارچگی ثبت می‌شود (پایین). |
| تفکیک کارشناس تماس / کارشناس خدمات پس از فروش | مسیر فقط توسط کارشناس تماس تخصیص‌یافته (یا مدیر CRM، D-07) انتخاب می‌شود. فرم تعیین نتیجهٔ نارضایتی فقط برای نقش‌های نارضایتی است. |

## ۴. مرز یکپارچگی بیاوین

```text
CRM رضایت‌سازی → مسیر مشتری = خدمات مازاد → select_services()
   → Workflow_Service::record_additional_services_boundary()
       activity «additional_services_boundary» {route, service_case_ids, service_ids, biawin_status: NOT_SENT, external_call: false}
       do_action('bcrm_additional_services_boundary', $customer_id, $payload)
   → [Phase 9] CRM فروش بیاوین + عملیات و اجرا (قرارداد واقعی؛ D-06 باز)
```

- هیچ endpoint، فیلد یا درخواست HTTP اختراع نشده است. در کل افزونه هیچ `wp_remote_*` وجود ندارد و در آزمون واقعی ۰ درخواست HTTP ثبت شد.
- تنها نقطهٔ فراخوانی `select_services()` است. ناراضی، Complaint، عودت و تهاتر به این مرز نمی‌رسند.

## ۵. D-05 — وضعیت پایانی تخصیص برای «بدون خدمات» (اجرا نشد)

**یافته‌ها:**
- موتور هیچ وضعیت پایانی «تکمیل» ندارد. تخصیص‌ها پس از انتخاب مسیر فعال می‌مانند.
- اگر `completed` اضافه شود، این مشتریان در این بخش‌ها «تخصیص‌نیافته» دیده می‌شوند:
  - استخر «فقط تخصیص‌نیافته‌ها» (`handle_assignment`)؛
  - KPI «باقی‌مانده/تخصیص‌نیافته» (`reporting-assignment-service`، `reporting-consumer-adapter`)؛
  - workload کارشناس؛
  - Data Audit (`unassigned_customers`).
- در نتیجه آن‌ها ممکن است دوباره تخصیص شوند و گزارش‌های Source-of-Truth جابه‌جا می‌شوند.

**تغییر لازم (Phase بعد، پس از تأیید):**
1. مقدار `completed` در همان ستون (`completed_at`).
2. مستثنا کردن مشتریان بایگانی بدون خدمات از استخر و KPIهای «تخصیص‌نیافته».
3. به‌روزرسانی سرویس‌های گزارش و آزمون‌های SOT.

## ۶. مشتریان موجود «خدمات مازاد»

| پرسش | پاسخ |
|---|---|
| محل ذخیره | `customers.journey_state='service_request'` |
| نمایش مسیر | همان کلید. برچسب جدید «خدمات مازاد» است. |
| خدمات انتخابی | `service_cases` (کاتالوگ `service_catalog`، واحد `unit_key`) |
| پرونده خدمت دارند؟ | بستگی دارد. گزارش این تفکیک‌ها را می‌شمارد: با/بدون پرونده، وضعیت پرونده‌ها، رسیده از Outcome قدیمی نارضایتی، دارای خدمات واردشده از فایل مرجع (`services`)، و پرونده‌های خدمت روی مسیرهای دیگر. |
| داده بیاوین | **ندارد.** هیچ ستون، جدول یا شناسهٔ بیاوین در CRM رضایت‌سازی وجود ندارد. |
| تکرار | تعداد «مشتری + خدمت» فعال تکراری گزارش می‌شود؛ در آزمون = ۰ |
| اقدام | هیچ مهاجرت یا ارسالی انجام نشد. گزارش: wp-admin → «گزارش‌های مسیر مشتری» (فقط خواندنی). |
